### R-02 会话标题按首问自动提炼（P0）【已完成：规则提炼，LLM 开关默认关】

**目标**：新会话第一次提问并成功落库后，侧栏标题自动变成对该问题的简短提炼（≤16 字），而不是一堆「新会话」。

**触发时机**：某会话成功落库第 1 条记录时，且当前会话名为默认值（`新会话` / 空）。

**方案对比**

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A（推荐） | 规则提炼：去疑问词/语气词/换行/标点 → 截断至 16 字，超长加省略号 | 零额外成本、零延迟、结果稳定可预期 | 长问句可能截成半句 |
| B | LLM 提炼：首问并发调用一次小模型，产出 ≤16 字标题，失败回退方案 A | 标题质量更接近主流对话产品 | 多一次 LLM 调用，需处理失败与超时 |
| C | 前端即时截断，不落库 | 改动最小 | 刷新/换设备后丢失，且与后端列表不一致 |

**建议**：MVP 走 A，预留 B 的开关（`SESSION_TITLE_LLM_ENABLED`）。标题是导航辅助信息，稳定性优先于文采；当前首问已在检索/生成上耗时，不应再叠一次串行 LLM。

**关键约束**

1. **不覆盖用户手动重命名**：仅当 `session_name == 默认名` 时才自动生成；用户改过名后不再自动覆盖。
2. **只生成一次**：以「记录数 == 1」为条件，避免后续每轮都改名。
3. **下发方式**：在 `done` 帧中附带 `session_title`，前端就地更新侧栏，无需额外请求，避免发完消息再单独拉列表造成闪烁。
4. **失败静默**：标题生成失败不影响本次回答与落库。
5. **异常兜底**：首问为空、纯寒暄、纯符号或落库失败/被中断时，标题保持「新会话」。
6. **幂等**：后端条件更新应为 `WHERE session_name IN ('新会话','')`；重复 `done` 帧或并发回调不得反复改名。
7. **标题规范**：去除换行和多余空白，最长 16 字，超长使用省略号；标题全文通过 `title` 属性兜底。

**交互细节**：发送首问后侧栏当前项显示灰色占位「自动命名中…」，`done` 到达后淡入真实标题；标题超长两行截断。

**技术落点**：新增 `backend/services/session_title.py`（纯函数 `derive_title(query)` + 可选 LLM）；`chat_store` 增加 `maybe_set_auto_title(session_id, user_id, title)`；`chat.py` 在落库后调用并写入 `done` 帧。无需改表结构。

**验收**

- 新会话问「MySQL 的索引失效场景有哪些」→ 侧栏显示「MySQL 的索引失效场景」类标题（≤16 字）；
- 重命名后再提问，标题不再被自动改；
- 历史会话列表刷新后标题保持一致；
- 后端异常、回答被中断或未落库时，标题保持「新会话」，回答流程不受影响。

### R-05 工具状态时序与文案重做（P0 前端兜底 / P1 后端真实状态）【已完成】

**目标**：等待期间显示真实或可降级的进行中动画，结果返回后立刻变成结果描述，彻底消除「✔ 正在检索知识库…」。

**问题根因（已定位）**

1. `prompts.py` 的 `TOOL_LABELS` 写的是进行时文案，但 `graph.py` 各工具节点把 `status` 硬编码为 `done`；
2. `chat.py` 在 `_prepare()`（含检索/重排/LLM 决策）全部完成后才发 `tool` 帧，前端收到的第一条工具事件就是「已完成」；
3. `ToolChip` 据 `status` 选择 `✔`/`⏳`，于是渲染出 `✔ 正在检索知识库…`；
4. `ChatView` 另有一个 `tool-banner`，与气泡内 ToolChip 重复表达同一状态。

#### 5A. 前端兜底（P0，不依赖后端改造）

- 发送消息后 100ms 内显示「正在理解问题…」三点脉冲动画，不允许空白气泡；
- 若后端暂未发送 `running` 帧，收到 `done` 工具事件后直接切换完成态；
- 删除现有重复 `tool-banner`，状态条统一放在助手气泡内部顶部；
- 旧后端接口下，前端不得出现对勾 + 进行时文案的组合。

#### 5B. 后端真实状态生命周期（P1）

| 方案 | 做法 | 是否推荐 |
| --- | --- | --- |
| A | 后端补 `running` 帧：工具节点执行前通过回调/队列发出 `{status:"running"}`，结束再发 `{status:"done", result_count}`；`TOOL_LABELS` 拆成 `RUNNING_LABEL` / `DONE_LABEL` 两套 | 推荐，状态真实 |
| B | 纯前端模拟：发送即显示「正在理解问题…」，收到 `tool` 帧后直接切「已完成」 | 仅作降级，中间缺少真实「检索中」 |

**目标状态机**

```text
用户发送
  └─ 0ms        正在理解问题…            （三点脉冲动画）
  └─ 决策完成    正在检索知识库…          （旋转/扫描动画，真实处于检索中）
  └─ 检索返回    已检索知识库 · 命中 5 条来源   （✓ 静态，绿色）
  └─ 首 token    状态条收起为一行小标签（或折叠进消息元信息）
  └─ done        ⌄ 耗时 2.4s · 引用 5 条 · 已保存
```

**文案规范（进行时 vs 完成时）**

| 工具 | 进行中 | 已完成 |
| --- | --- | --- |
| knowledge_search | 正在检索知识库… | 已检索知识库 · 命中 N 条来源 |
| calculator | 正在计算… | 已完成计算：`1234*56 = 69104` |
| doc_stats | 正在统计文档数据… | 已统计：文档总数 12 份 |
| 无工具（寒暄） | 正在思考… | 直接出答案，不显示状态条 |

**视觉规范**

- 状态条位置：助手气泡内部顶部，替换现有 `ChatView.tool-banner`；
- 进行中：浅灰底胶囊 + 左侧 16px 环形进度/三点脉冲动画 + 文案；整体宽度自适应，高度 28px；
- 完成：同一位置切换为对勾图标 + 深灰文案，不换行、不换位置，150ms 淡入淡出；
- 多工具（多轮）：垂直堆叠，每行一个工具，最多显示 3 行，超出折叠为「另有 2 步」；
- 无障碍：`aria-live="polite"` 播报状态变化；动画遵循 `prefers-reduced-motion` 降级为静态文案。

**验收**

- 提问后 100ms 内出现「正在理解问题…」动画；
- 检索阶段能观察到「正在检索知识库…」，且该文案生命周期内不出现对勾；
- 结果返回后文案在同位置变为「已检索知识库 · 命中 N 条来源」，N 与实际来源数一致；
- 全程无 `✔ 正在…` 组合；
- 旧后端未升级时，前端降级显示初始理解态和完成态，不报错、不空白。

### R-06 消息富文本渲染（P0）【已完成】

**目标**：答案支持 Markdown（标题、列表、表格、引用、行内代码、代码块）、代码高亮、链接安全跳转，样式贴近主流产品。

**技术选型**

| 能力 | 选型 | 理由 |
| --- | --- | --- |
| Markdown 解析 | `marked` | 快、GFM 支持表格/删除线，流式友好 |
| XSS 防护 | `dompurify` | 必须；LLM 输出与文档内容均不可信 |
| 代码高亮 | `highlight.js`（按需注册常用语言） | 成熟；只注册 `js/ts/python/java/sql/bash/json/yaml`，控制体积 |
| 复制按钮 | 自研小组件 | 代码块右上角 + 整条消息右下角 |

**安全规则**

- 允许解析 Markdown，禁用原始 HTML（`marked` 配置 + DOMPurify 白名单双保险）；
- 链接仅允许 `http/https/mailto`，统一 `target="_blank" rel="noopener noreferrer"`；
- 禁止 `script / iframe / on* 事件属性 / javascript: 链接 / 内联事件`；
- DOMPurify 在 Markdown 解析输出之后执行；
- 渲染失败回退纯文本 + 单行提示，不允许白屏。

**流式与性能规则**

- Markdown 解析器、DOMPurify、高亮库优先动态导入，不阻塞首屏；
- 流式期间内容每累积 ≥60ms 或一帧渲染一次（`requestAnimationFrame` 节流），避免每个 token 全量重解析；
- 代码块在未闭合时按纯文本预渲染，闭合后再高亮；
- `highlight.js` 只注册常用语言，不引入完整语言包；
- 流式输出 1000 字过程中不出现明显卡顿，Chrome Performance 无 >50ms 长任务。

**排版规则**

- 表格：外层 `overflow-x:auto`，禁止撑破气泡（`table-layout:auto` + `max-width:100%`）；
- 代码块：深色背景、等宽字体、右上角语言标签 + 复制按钮、横向滚动；行号可选（P2）；
- 行内代码：浅灰底 + 圆角 4px + 等宽字体，与正文基线对齐；
- 段落间距 8px，列表缩进 1.4em，引用块左侧 3px 竖线 + 浅灰底；
- 气泡内 `white-space` 由 `pre-wrap` 改为 `normal`；纯文本降级时保留 `pre-wrap`；
- 复制代码/消息时复制 Markdown 原文，不复制渲染后的 HTML 文本。

**样式基线（浅色主题）**

| 元素 | 规格 |
| --- | --- |
| 正文字号 / 行高 | 14px / 1.75 |
| 代码字号 | 13px |
| 气泡圆角 | 12px（助手）/ 12px 12px 4px 12px（用户） |
| 最大宽度 | 助手 78%（含头像占位后），用户 76% |
| 链接色 | `#2563eb`，hover 下划线 |

**验收**

- 回答含「有序列表 + 表格 + Python 代码块 + 行内代码」时，四类元素均正确渲染且无横向溢出；
- 代码块可一键复制，复制内容与原文一致（不含行号）；
- 注入 `<img src=x onerror=alert(1)>`、`<script>`、`javascript:` 链接等测试输入不执行脚本；
- 流式输出 1000 字过程中无明显卡顿；
- 渲染异常时回退纯文本，不出现白屏或残留 HTML。

### R-19 异常与流式恢复（P1）【已完成】

**目标**：让用户在网络、模型、数据库、会话权限或中断场景下知道发生了什么、能否重试。

**状态分类**

| 场景 | 前端表现 | 恢复动作 |
| --- | --- | --- |
| 网络断开 / SSE 读取异常 | 错误卡片：「连接中断，请重试」 | 提供重试按钮，保留原问题 |
| HTTP 4xx / 5xx | 展示后端 `msg` 和业务错误码 | 可重试项提供重试；参数类错误提示修正后再发 |
| 模型服务不可用 | 错误卡片：「模型服务暂时不可用」 | 稍后重试 |
| 会话不存在 / 无权限（40402） | 清空失效选中态，提示会话已失效或无权访问 | 引导新建会话 |
| 登录过期（40101 / 401） | 全局处理回登录页 | 重新登录后进入原应用 |
| 无权限（40303 / 403） | 提示「没有操作权限」 | 不暴露他人数据 |
| 用户主动中断 | 标注「已中断回答」，保留已生成部分内容 | 可重新发送或继续提问 |

**规则**

- 错误信息不只拼接到正文末尾，应使用独立错误卡片/提示区；
- 已生成的部分答案在中断时保留，但明确标注「未完成」；
- 长时间无首 token 时给出超时提示，避免一直停留在动画态；
- 重试按钮复用原问题，避免用户重新输入；
- 落库失败（`saved=false`）需明确提示本次回答未进入历史，但不把正常回答标记为系统错误。

**验收**

- 各类错误场景有区分文案和对应恢复入口；
- 主动中断后输入框恢复可用，草稿和部分答案不丢失；
- 会话失效后不保留他人或不存在会话的消息；
- 401/403 处理与现有全局错误拦截保持一致。

## 六、验收标准（可逐条勾选）

### 本轮 P0

1. 全站界面文案不含 `RagKnowledge`，顶栏、登录页、浏览器标题、favicon 品牌一致。
2. 新会话首问后 3 秒内，侧栏出现 ≤16 字的提炼标题；手动重命名过的会话不被覆盖；未落库/中断场景不生成标题。
3. 命中 5 条来源时，默认折叠态来源区总高 ≤240px；单条可展开；老会话记录不报错。
4. 每条消息有头像，主客可 0.5 秒辨识；头像与气泡顶对齐。
5. 提问后 100ms 内出现「正在理解问题…」动画；检索阶段显示进行中文案且不带对勾；完成后同位置切换完成态。
6. 含列表/表格/代码块的回答正确渲染、可复制代码、无 XSS；流式 1000 字无明显卡顿。

### 本轮 P1

7. 上滑阅读时页面不被强行拉回底部，出现「↓ 新消息」按钮。
8. 空会话显示示例问题，点击可直接完成问答。

10. 消息可复制 Markdown 原文与重试，气泡底部显示真实耗时和来源数。
11. 正文 `[1]` 角标可点击定位并高亮对应来源；无效角标保持纯文本。
12. 输入框随内容增高，流式中仍可输入，仅发送被禁用；失败/中断保留草稿。

### 回归项（不得退化）

21. Markdown/XSS 测试输入不执行脚本；复制代码内容与原文一致。
22. 新增 Markdown/高亮依赖不得显著增大首屏包体，优先按需加载。
