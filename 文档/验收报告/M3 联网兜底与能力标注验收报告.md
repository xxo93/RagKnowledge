## 1. 本阶段做了什么

| 能力 | 行为 |
|---|---|
| 内部知识不足判定 | 阈值过滤后有效命中 **< FALLBACK_MIN_HITS（默认 2）** 即判"知识不足"，不再拿 1 条残片硬答 |
| 兜底方式 | `FALLBACK_MODE` 三选一：`web`（联网）/ `guide`（引导补充描述）/ `contact_admin`（联系管理员），配置中心可热切换 |
| 联网检索 | 新增 `services/web_search.py`，支持 **博查（bocha，默认）** 与 Tavily；`WEB_SEARCH_*` 走 `.env`，Key 与 LLM Key 隔离，需显式 `WEB_SEARCH_REUSE_LLM_KEY=true` 才允许复用 |
| 能力标注 | 联网回答上方固定展示「联网检索 · 非内部知识」标签 + 提示条："本条回答来自联网检索，不属于企业内部知识库能力，仅供参考。" |
| 失败兜底 | 未配置 / 关闭 / 超时 / 非 200 / 空结果 **一律回落 `contact_admin` 话术**，并带 `WEB_SEARCH_UNAVAILABLE` 提示说明原因；绝不用模型自答冒充联网 |
| 来源展示 | 联网来源 `source_type=web`，带可点击 `url`、站点名、摘要；来源区标题变「🌐 联网来源」，卡片带「联网」标签，无"相似度 0.00"这类误导分数 |
| 历史回放 | `chat_record.answer_mode` 落库，刷新/换设备后仍能标出"这条不是内部知识库答的" |
| 状态灯 | 顶栏「联网」灯改由 `web_search.is_ready()` 判断（开关 + 搜索 Key 双条件），并跟随配置中心热开关 |

## 8. M3.1 追加：搜索源切到阿里百炼 + 搜索源可配置（2026-11-11）

### 8.1 为什么百炼可行、而 DeepSeek Key 不行

| 路线 | 结论 |
|---|---|
| `LLM_API_KEY`（DeepSeek `sk-`）当搜索 Key | ❌ 跨厂商鉴权不通，DeepSeek 无检索接口，且等于把模型 Key 发给第三方 |
| 百炼 **IQS 信息查询服务**（`cloud-iqs.aliyuncs.com`） | ❌ 要单独申请 IQS 的 API-KEY 并开通计费，`EMBEDDING_API_KEY` 不是 IQS 凭据 |
| 百炼 **联网搜索（DashScope `enable_search`）** | ✅ 同一账号的 DashScope Key 即可用；`search_options{forced_search, enable_source}` 能返回 `search_info.search_results[]` 结构化来源 |

所以本阶段走的是第 3 条：百炼联网问答，一次调用同时拿到"有搜索依据的答案"和"来源列表"，正好复用账号里已有的 `EMBEDDING_API_KEY` 值。

### 8.2 实现要点

- **Key 变量独立**：新增 `BAILIAN_SEARCH_API_KEY`（`.env` 已写入，值同 `EMBEDDING_API_KEY`，长度 115）。原变量一字未改；`BAILIAN_SEARCH_API_KEY` 为空时才回落到 `EMBEDDING_API_KEY`（同厂商，不算跨厂商借 Key），便于以后单独轮换/停用搜索能力而不影响向量化。
- **调用形态**：`POST {base}/services/aigc/text-generation/generation`，body 带
  `enable_search=true` + `search_options{forced_search:true, enable_source:true, search_strategy:turbo}` + `result_format:message`；
  `forced_search` 保证兜底场景一定真联网，`enable_source` 保证来源可展示。
- **答案来源**：百炼直接返回 grounded 答案（带 `[1][2]` 角标），所以这条链路**不再用 DeepSeek 二次生成**，只把答案按 SSR token 帧下发；博查/Tavily 仍走原来的"片段 + LLM 生成"。
- **解析字段**：`output.search_info.search_results[]` 实测只有 `icon/site_name/index/title/url`（没有 snippet），因此来源卡片摘要用"来源站点：{site_name}"兜底，避免空白行。
- **系统提示**：给百炼加了 system 提示（只依据本次检索、不重复免责声明、用 `[n]` 标注、不足就说不足、不编造链接），避免它张口说"根据知识库信息"。
- **搜索源可配置**（配置中心 → 兜底，参数 17 → 22）：
  | 参数 | 类型/范围 | 说明 |
  |---|---|---|
  | `WEB_SEARCH_PROVIDER` | enum `bailian` / `bocha` / `tavily` | 热切换搜索源；切换后地址与 Key 归属跟着变 |
  | `WEB_SEARCH_MODEL` | str ≤500 | 百炼联网模型，默认 `qwen-plus`，留空用默认 |
  | `WEB_SEARCH_BASE_URL` | str ≤500 | 留空＝供应商默认地址（百炼 `https://dashscope.aliyuncs.com/api/v1`） |
  | `WEB_SEARCH_MAX_RESULTS` | int 1–10 | 参与来源展示与作答的网页条数 |
  | `WEB_SEARCH_TIMEOUT` | float 3–60 | 默认 20s（百炼是"搜索+生成"，比纯搜索慢） |
- **热生效**：同步链路 `web_search` 通过新加的 `app_config.runtime_value()` 读运行时值（配置中心覆盖 > `.env` > 代码默认），与异步链路的 `get_value()` 语义一致；顶栏「联网」灯同时看**开关 + 当前供应商的 Key + 模型名**。
- **密钥仍不进页面**：配置页继续只维护 provider/model/地址/条数/超时，密钥留在 `.env`（页面标题下已注明）。

### 8.5 仍然存在的限制

1. 百炼来源**没有摘要片段**，卡片只能显示站点名 + 标题 + 链接；若想要摘要需另接 IQS 或网页抓取（成本/额度另算）。
2. 百炼联网按"搜索 + token"计费，题目越多成本越高；`WEB_SEARCH_MAX_RESULTS` 与 `FALLBACK_MIN_HITS` 是控制成本的两个旋钮。
3. `enable_search` 依赖账号已开通对应模型与联网能力；若换成未开通的模型，会返回 4xx，此时按 `WEB_SEARCH_HTTP_ERROR` 回落联系管理员（已覆盖）。
4. 切换 `bocha`/`tavily` 需自行填 `WEB_SEARCH_API_KEY`，未填时状态灯为灰、问答回落联系管理员（已实测）。
