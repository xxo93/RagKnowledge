## 二、数据模型变更（已在本机库实测生效）

```sql
-- chat_session
ALTER TABLE chat_session ADD COLUMN summary TEXT;
ALTER TABLE chat_session ADD COLUMN summarized_until_record_id BIGINT;
ALTER TABLE chat_session ADD COLUMN memory_enabled BOOLEAN NOT NULL DEFAULT TRUE;

-- chat_record
ALTER TABLE chat_record ADD COLUMN answer_digest TEXT;
ALTER TABLE chat_record ADD COLUMN prompt_tokens INT;
ALTER TABLE chat_record ADD COLUMN completion_tokens INT;

-- 新表
CREATE TABLE session_memory (
  mem_id BIGSERIAL PRIMARY KEY,
  session_id BIGINT NOT NULL REFERENCES chat_session(session_id) ON DELETE CASCADE,
  user_id BIGINT NOT NULL REFERENCES sys_user(user_id) ON DELETE CASCADE,
  kind VARCHAR(16) NOT NULL CHECK (kind IN ('constraint','fact','entity','todo')),
  fact_key VARCHAR(64) NOT NULL,
  fact_value TEXT NOT NULL,
  confidence DOUBLE PRECISION NOT NULL DEFAULT 0,
  source_record_id BIGINT NULL,
  invalidated_at TIMESTAMP NULL,
  create_time TIMESTAMP NOT NULL DEFAULT NOW(),
  update_time TIMESTAMP NOT NULL DEFAULT NOW()
);
-- 同 key 仅一条 active（软失效保留历史，便于审计）
CREATE UNIQUE INDEX uq_session_memory_active_key
  ON session_memory(session_id, fact_key) WHERE invalidated_at IS NULL;
```

存量库无需手工迁移：`chat_store.ensure_record_schema()` 与 `session_memory_store.ensure_memory_schema()` 在应用启动时幂等补齐（`ADD COLUMN IF NOT EXISTS` / `CREATE TABLE IF NOT EXISTS`），`backend/init_db.sql` 同步更新供全新部署使用。

| 方法 | 路径 | 说明 | 越权行为 |
|---|---|---|---|
| GET | `/api/sessions/{session_id}/memory` | 事实 + 摘要 + `context_usage` | 他人会话 → 404 / `40402` |

## 四、上下文注入与预算算法

固定顺序（`rag.build_prompt`）：

```
系统提示 → 会话事实块 → 滚动摘要块 → 最近 N 轮原文 → 检索资料 → 本轮问题
```

预算策略（`memory.build_context`）：

1. 从最新一轮往旧装填，每轮先压 `answer_digest`（头 300 字 + 尾 150 字），整轮再受 `HISTORY_TURN_MAX_TOKENS=400` 限制；
2. 事实块 + 摘要块先占预算（保底信息），原文按剩余预算倒序装填；
3. 记录 `dropped_rounds`，`total_tokens` 含事实/摘要/原文三部分；
4. token 估算为**保守近似**（CJK 1 token/字、其它 1/4 字符），`usage.token_estimator` 明示口径，避免把估算当真实计费；
5. 临时会话（`memory_enabled=false`）不注入事实与摘要，`context_usage` 直接反映 `facts_count=0`、`summary_chars=0`。

摘要与事实抽取都在 **done 帧之后**以 `asyncio.create_task` 异步执行，异常被 `summarize_async/extract_async` 吞掉，失败不阻塞问答、不影响本轮回答落库。

## 八、验收中发现并修复的问题

1. **验收脚本 SSE 解析误判**（首轮 6 项 FAIL）：`resp.iter_lines()` 会把 `event:` 与 `data:` 粘到一行，行首 `startswith` 匹配不到。改为整段 `resp.text` 按行匹配后，6 项全部转 PASS。**属于脚本问题，后端 done 帧本身输出正确。**
2. **抽屉渲染错位**（首轮 UI 截图只露出右边缘 80px）：`el-drawer` 默认不挂到 body，被 `el-row` 的布局与裁切影响。加 `append-to-body` 后完整落在视口内。
3. **375 窄屏抽屉被裁切**：`size="400px"` 固定宽度超过视口。改为视口 <480 时 `100%`，并监听 resize；重新构建后 375 截图完整。

以上三处均已复测通过，**无后端逻辑缺陷**。

## 九、已知限制与取舍

1. token 为**保守估算**，不是模型真实 tokenizer；用于预算治理与观测，不作为计费口径（`usage.token_estimator` 明示）。
2. 摘要与事实抽取为异步后台任务，进程重启会丢失当轮未完成的任务；失败只记日志，不重试、不阻塞问答。
3. 事实抽取按"总轮次 % 4 == 0"触发且只看最近 2 轮，长会话中较早的口径依赖摘要保留；LLM 抽取失败时回退规则抽取（记住/单位是/项目叫/待办）。
4. 记忆面板只展示当前会话，不提供跨会话的"用户画像"；跨会话长期记忆属后续阶段议题。
5. 新接口前缀 `/api/sessions/{id}/memory` 与旧 `/api/chat/session` 并存（按需求原文实现），旧的会话 CRUD 前缀未迁移。
6. 离线评测是装配级，不替代真实问答级评测；如需真实模型评测需另开开关与预算（会产生调用费用）。
