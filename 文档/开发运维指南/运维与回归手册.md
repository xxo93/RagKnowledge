# RagKnowledge · 运维与回归手册

适用范围：本地演示环境的启动、健康判据、分级回归、轻量离线 CI、数据生命周期、账号与权限运维、关键开关与常见排障。
本文只描述已落地实现；未实现能力（Docker、部署发布、异步队列、OCR、Milvus 等）在文末边界节集中说明。

## 1. 前置环境

| 组件 | 版本/要求 | 说明 |
| --- | --- | --- |
| Python | 3.12（兼容 3.10+） | 后端 `.venv`；依赖见 `backend/requirements.txt`（含 `pytest>=8.0`） |
| Node.js | 20 左右 | 前端 `frontend/`，含 `package-lock.json`，生产构建 `vite build` |
| PostgreSQL | 16/17 + pgvector 扩展 | 库 `rag_agent`；业务表 + `document_chunk.embedding vector(1024)` + HNSW `vector_cosine_ops` |
| 配置文件 | `.env`（不入库、见 `.gitignore`） | `DB_DSN`、`LLM_API_KEY`、`EMBEDDING_API_KEY`；`.env` 含真实密钥禁止提交 |

安装依赖：

```powershell
# 在仓库根目录 D:\code\code_git\RagKnowledge 下执行
python -m venv .venv ; .venv\Scripts\activate
python -m pip install -r backend\requirements.txt

cd frontend
npm install        # CI 使用 npm ci；本地首次可用 npm install
```

## 2. 启动顺序

> 顺序：PostgreSQL（`127.0.0.1:5432/rag_agent`）→ 后端 8000 → 前端 5173。

```powershell
# 1) 幂等建库建表（仅首次/需要重建时）
python backend\scripts\create_database.py
python backend\scripts\init_db.py          # 渲染维度并建扩展/表/HNSW，结束回读校验

# 2) 后端（Windows 推荐经 run_dev.py 的 SelectorEventLoop；勿裸 uvicorn）
python backend\scripts\run_dev.py          # 入口 backend.main:app，http://127.0.0.1:8000

# 3) 前端（另开终端）
cd frontend
npm run dev                        # http://127.0.0.1:5173，代理 /api -> 8000
```

接口文档：`http://127.0.0.1:8000/docs`；健康检查 `GET /health`；配置元信息 `GET /api/system/info`。

## 3. 健康与就绪判据

- `GET /health`：`status=up`、`db_ready=true` 表示连接池就绪；`db_ready=false` 时服务仍能启动，但依赖数据库的业务接口返回 50001。
- `GET /api/system/info`：`db_ready=true`、`doc_total`/`chunk_total` 与库内计数一致；离线（未建池）时统计量为 `null`、接口仍返回 200。
- 权威基线（B 档复评清理后）：`document=4、document_chunk=4、chat_session=0、chat_record=0`；留存样料 doc_id 9/10/11/13，均 `status=1、chunk_count=1`。

## 4. 分级回归（按是否调用模型 / 是否需要数据库划分）

### 4.1 纯离线、零模型调用（推荐日常执行；无网络费用）

一键本地镜像（后端三步；加 `-Frontend` 追加 `npm ci` 与 `vite build`）：

```powershell
powershell -ExecutionPolicy Bypass -File backend\scripts\offline_regression.ps1
powershell -ExecutionPolicy Bypass -File backend\scripts\offline_regression.ps1 -Frontend
```

等价单步（`cwd=仓库根`）：

```powershell
python -m pytest backend/tests -q  # 纯函数/解析层/防重复/心跳/再规划/鉴权 API 单测
python backend\scripts\check_env.py # 第三方与内部模块导入、FastAPI 装配、/api 路由；不连库不调模型
python -m compileall -q backend     # 静态字节编译（只编译不执行、不联网）
cd frontend ; npm run build         # 前端生产构建；chunk>500kB 为非阻塞警告
```

### 4.2 需要本地 PostgreSQL、但不调用模型（无模型费用）

```powershell
# 工作目录 = 仓库根
python backend\scripts\check_chat_sse.py    # SSE 帧契约/降级/落库；REAL_LLM 默认 SKIP，DB 不可用时对应项 SKIP
python backend\scripts\check_hnsw_index.py  # 事务内造合成向量验证 HNSW Index Scan，结束回滚、不留数据
```

### 4.3 联网按需（产生 Embedding/Rerank/LLM 调用费；写库类脚本测完自动清理）

```powershell
# 工作目录 = 仓库根
python backend\scripts\check_rerank.py             # gte-rerank-v2 真实排序 + 坏端点降级探针
python backend\scripts\assess_retrieval.py        # 留存样料召回基线 Hit@K/MRR（复用已入库向量，仍会向量化查询）
python backend\scripts\assess_rerank_gain.py       # B 档：内嵌 10 篇测试语料入库，OFF 纯向量/ON 重排对比，自动清理复原
python backend\scripts\check_docx_pdf_ingest.py    # DOCX/PDF 真实入库命中验证，脚本内关 rerank、测完清理
python backend\scripts\check_maintenance.py        # C 档：临时文档重解析事务替换切片 + HNSW REINDEX；自动删除临时记录/文件，不重嵌入留存样料
# check_replan_live.py 默认离线零调用；$env:REPLAN_LIVE="1" 才发起 1 次真实 LLM 再决策、不写库
```

### 4.4 运维 HTTP 接口（服务运行中可用；重解析会产生少量 Embedding 调用，REINDEX 无模型费用）

| 方法/路径 | 用途 | 边界与注意 |
| --- | --- | --- |
| `POST /api/docs/upload/batch` | 多文件服务端顺序入库，返回 `success/failed` 明细与计数 | 非并发、无异步队列；单文件失败不中断其余文件；保留单文件 `/upload` 兼容 |
| `POST /api/docs/{doc_id}/reparse` | 重读原件、重切片、重嵌入并事务替换切片 | 保留 `doc_id` 与元数据；留存样料默认不主动重跑；原件缺失时返回处理失败 |
| `POST /api/docs/reindex` | `REINDEX idx_chunk_embedding` 重建 HNSW 索引 | 纯 DDL，不改变文档内容、不产生模型费用；重建期间尽量避免并发大量写入 |

## 5. 轻量离线 CI（`.github/workflows/ci.yml`）

- 触发：push 到 `main`、以及面向 `main` 的 Pull Request。
- `backend-offline`（ubuntu + Python 3.12）：安装 `backend/requirements.txt` → 仓库根 `pytest backend/tests -q` → `backend/scripts/check_env.py` → `compileall backend`。
- `frontend-build`（ubuntu + Node 20）：`npm ci` → `npm run build`。
- **刻意不纳入**：依赖 PostgreSQL 的脚本、真实 Embedding/Rerank/LLM 调用、密钥与部署发布；因此流水线可在无密钥的干净环境稳定运行。本地 `offline_regression.ps1` 与后端作业等价；前端作业在本地以 `npm run build` 等价验证（首次依赖安装与 `npm ci` 在 CI 完成）。
- 说明：工作流文件已就位且 YAML 可解析、等价步骤本地全绿；首次在 GitHub 实际跑批需推送仓库后由 Actions 执行。

## 6. 数据生命周期与清理纪律

- 留存样料：doc_id 9/10/11/13 长期保留，禁止在评测脚本中删除。
- 测试文档：评测脚本以 `beval_*`、`maint_temp.md` 等临时前缀/名称入库；`finally` 先 `delete_document`（同事务先删 `document_chunk` 再删 `document`，FK 级联），再按 `document.file_path` 删除 `data/uploads/` 下对应落盘文件。
- 后端删除接口只清数据库、不 `unlink` 本地文件；需要完全清理时由评测脚本统一处理。
- 会话与记录：演示产生的 `chat_session/chat_record` 用完应删除，权威计数保持 `0/0`。
- 仓库内历史孤儿留档文件（DB 无记录）保持现状、不擅自删除。

## 7. 关键配置开关（`config.py` / `.env`；生产阈值不随评测修改）

| 配置 | 默认/当前 | 作用与边界 |
| --- | --- | --- |
| `TOP_K` | 5 | 向量召回与重排保留条数上限 |
| `RETRIEVAL_MIN_SCORE` | 0.0 | 应用层相似度阈值；`0.0` 不过滤。B 档复评建议维持 0.0、不收紧（小样本 gold-非gold 间隙仅 +0.0449） |
| `CHUNK_SIZE / CHUNK_OVERLAP` | 500 / 100 | 切片窗口与重叠，重叠必须小于窗口 |
| `RERANK_ENABLED` | 代码默认 False；`.env` 示例/线上可置 true | true 时向量 Top-K 候选经 gte-rerank-v2 重排并附 `rerank_score`；失败/无 Key 一律回退向量原序；`score` 恒为向量余弦分、不被重排覆盖 |
| `RERANK_TOP_N / RERANK_TIMEOUT` | 5 / 10 秒 | 重排保留数；超时降级原序 |
| `HNSW_EF_SEARCH` | 40 | 检索 GUC（独立可回滚事务设置，版本不支持则容错跳过） |
| `MAX_TOOL_ROUNDS` | 3 | Agent 再循环上限，防死循环 |
| `HISTORY_ROUNDS` | 5 | 注入 LLM 的最近会话轮数 |
| `MULTI_ROUND_ENABLED` | True | 主循环是否允许再规划回跳 |
| `LLM_REPLAN_ENABLED` | False | True 才调 LLM 再决策（增加 LLM 调用）；默认 False 时 `plan_next` 确定性收敛、零额外 LLM 费用 |
| `UPLOAD_MAX_MB` | 10 MB | 上传大小上限 |

## 8. 费用与密钥纪律

- Embedding：百炼 `text-embedding-v3`、1024 维、OpenAI 兼容协议；单批 ≤10 行（`EMBEDDING_BATCH_SIZE=10`）。
- Rerank：`gte-rerank-v2` 原生 HTTP 端点，复用 `EMBEDDING_API_KEY`，无独立 Rerank Key。
- 默认优先离线命令；联网脚本规模保持保守、写库测试一律自动清理；不把测试密钥写入代码或提交 `.env`。

## 9. 常见排障

| 现象 | 排查方向 |
| --- | --- |
| `/health db_ready=false` 或接口 50001 | PostgreSQL 未启动、`DB_DSN` 不通、`init_db.py` 未执行；服务本身不崩，仅 DB 相关接口不可用 |
| Windows 裸 `uvicorn main:app` 下 psycopg 异步连接报错 | Proactor 事件循环与异步 psycopg 不兼容；改用 `python backend\scripts\run_dev.py`（SelectorEventLoop） |
| 前端构建提示 chunk >500 kB | 仅体积警告、不阻断构建；当前功能演示可忽略，按需再做代码分割 |
| Rerank 未改变顺序 | 开关关闭、无 Key、超时/非 2xx/结构为空都会降级向量原序；查看 `rag.reranker` 日志确认 |
| 无命中返回固定话术 | 不调用 LLM、不编造答案；先确认文档已成功入库且向量召回非空 |
| 评测脚本退出码 1 | 区分“指标低于观察线（如实记录、非报错）”与“清理未复原/异常”；以末行 `EVAL_RESULT` / `RERANK_GAIN_RESULT` / `RERANK_CLEANUP` 为准 |

## 10. 账号与权限运维（V2.2）

### 10.1 默认管理员与首次初始化

默认超级账号在 `backend/config.py` 中配置（可被 `.env` / 环境变量覆盖）：

```ini
DEFAULT_ADMIN_USERNAME=admin
DEFAULT_ADMIN_PASSWORD=Admin@12345      # 置空则随机生成，仅在控制台打印一次
DEFAULT_ADMIN_DISPLAY_NAME=系统管理员
DEMO_CREDENTIAL_HINT=false              # 登录页是否显示演示账号提示（默认关闭，生产勿开）
```

> 开启 `DEMO_CREDENTIAL_HINT` 后，`GET /api/auth/demo-hint` 才会返回明文账号密码，且仅在默认密码
> 仍可登录时返回；改密/禁用后自动隐藏。前端登录页据此显示提示并提供「一键填入」。

```powershell
python backend\scripts\migrate_auth_multitenant.py  # 幂等：建认证/审计表、会话归属，并按配置创建默认管理员
python backend\scripts\ensure_admin.py              # 幂等：缺则创建；已存在则不改密码
python backend\scripts\ensure_admin.py --reset-password   # 强制重置为配置密码并吊销其登录态（找回密码用）
```

- 迁移输出 `SEED_ADMIN_CREATED=YES username=...`；密码置空时输出 `SEED_ADMIN_TEMP_PASSWORD=...`，请立即登录并修改。
- 输出 `TABLE_COUNTS=...` 便于迁移前后核对；`CHAT_SESSION_USER_ID_NOT_NULL=YES` 表示约束已补。
- 重复执行安全：已存在管理员时不再创建，`ensure_admin.py` 默认也不覆盖已有密码。
- 生产部署：覆盖为强密码或置空随机，并登录后改密；默认值仅为本机演示便利。

### 10.2 日常操作

| 场景 | 操作 |
| --- | --- |
| 新建账号 | 管理员登录后进入顶部「用户管理」→「新建账号」；或调用 `POST /api/admin/users`（`role=member\|admin`） |
| 禁用/启用账号 | 「用户管理」行内「禁用/启用」；等价 `PATCH /api/admin/users/{id}/status {"status":0\|1}`，禁用会同步吊销其全部登录态 |
| 重置他人密码 | 「用户管理」行内「重置密码」；等价 `POST /api/admin/users/{id}/reset-password {"new_password":"..."}`，同步吊销其登录态 |
| 修改自己的密码 | 前端右上角「修改密码」或 `POST /api/auth/password` |
| 查看审计 | `SELECT created_at, actor_user_id, action, target_id, result, detail FROM operation_log ORDER BY log_id DESC LIMIT 50;`（不含聊天内容） |
| 强制下线某人 | `UPDATE auth_session SET revoked_at = now() WHERE user_id = ? AND revoked_at IS NULL;` |

防呆规则：不能禁用自己；不能禁用最后一个启用中的 admin（避免把自己锁在门外）。

### 10.3 鉴权排障

| 现象 | 原因/处理 |
| --- | --- |
| 接口返回 `40001 参数校验失败：query.request Field required` | 鉴权依赖缺少 `request: Request` 注解（历史缺陷）；检查 `services/auth_deps.py` |
| 登录成功但立刻回登录页 | 浏览器拒绝/未携带 Cookie；确认经 Vite 代理同源访问（`/api`），而非直接跨域打 8000 |
| 全部接口 401 | Cookie 过期或被吊销（改密/重置/禁用都会吊销）；重新登录 |
| 普通用户看到 40303 | 正常：管理接口仅 admin；前端隐藏菜单只是体验 |
| 需要强制所有人重新登录 | `UPDATE auth_session SET revoked_at = now() WHERE revoked_at IS NULL;` |

## 11. 明确边界（不做项）

OAuth/OIDC/SSO、自助注册、文档级 ACL、细粒度 RBAC、Docker 化与部署发布、异步任务队列、扫描件/图片型 PDF 的 OCR、Milvus 等外部向量集群；真实业务大语料下的阈值收紧与 Rerank 显著增益验证，需在获得真实文档后另立评测；当前轻量 CI 只做构建/单测/装配校验，不接数据库与发布流程（认证相关集成校验通过 `scripts/check_auth_http.py` 本地执行）。
